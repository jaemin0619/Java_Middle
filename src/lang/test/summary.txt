모든 클래스를 불변으로 만드는 것은 아님.

-> 예를 들어서 회원 클래스의 경우 회원의 여러 속성을 변경할 수 있어야 함. 가변 클래스가 더 일반적이고, 불변 클래스는 값을 변경하면 안되는
특별한 경우에 만들어서 사용된다고 보면 됨.

클래스를 불변으로 설계하는 이유
1. 캐시 안정성
2. 멀티 쓰레드 안정성
3. 엔티티의 값 타입

기본형: 하나의 값을 여러 변수에서 절대로 공유 x
참조형: 하나의 객체를 참조값을 통해  여러 변수에서 공유 o

기본형 변수는 b=a라고 하면 자바는 항상 값을 복사해서 대입
참조형 변수는 참조해서 대입 (인스턴스 참조)

참조값 변경 시 모든 값이 바뀌는 현상 = 사이드이펙트
메인 작업이 아닌 갑자기 다른 곳에서 다 터지는 현상 = 사이드이펙트

여러 변수가 하나의 객체를 공유하는 것을 막을 방법은 x

참조값의 공유를 막을 수 있는 방법은 없음

불변 객체 - 도입
아예 값을 바꿀 수 없는 값 도입
불변이라는 단순한 제약을 사용해서 사이드 이펙트라는 큰 문제를 막을 수 있음

가변 객체 vs 불변 객체
가변 클래스에서 객체 생성시 가변 객체
불변 클래스에서 객체 생성시 불변 객체
